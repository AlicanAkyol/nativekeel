21 October 2026

A critical, actively exploited React Native vulnerability, found even when it hides in your lockfile.

  • SecurityMetro development-server RCE (CVE-2025-11953). The Metro dev server's /open-url endpoint in @react-native-community/cli / cli-server-api runs OS commands from a request (CVSS 9.8, in CISA's Known Exploited Vulnerabilities list): while react-native start runs, a web page a developer opens can take over their machine. 0.1.117

21 October 2026

The question every team asks before an upgrade, answered directly: npx nativekeel upgrade.

  • NewUpgrade readiness. npx nativekeel upgrade gives a go/no-go for moving to the newest React Native / Expo: what breaks in your code and dependencies, with file and line, as blockers; behavior and tooling changes to review; and a clear verdict — READY, NOT READY (with the blockers), a multi-version jump (upgrade one step at a time), or already current. It exits 1 when blockers remain, so a CI job can gate the upgrade pull request. Also the MCP tool upgrade_readiness for AI agents.
  • TrustHonest about multi-version jumps. An app several versions behind is never shown a clean "ready": the verdict says the catalog covers the newest step and the earlier steps have their own breaking changes, and points to plan for the staged path.
  • FixFewer false alarms in the expo-file-system change. File.write() becoming async is now flagged only on a real new File(...) instance, not on any .write() in a file that happens to import expo-file-system (a database transaction was being flagged).

0.1.116

21 October 2026

A reliability release from a third production review, with no new checks: outputs that crashed, a comparison that missed regressions, and labels that claimed more than the scan knew.

  • FixSARIF export no longer stops. A finding with several locations made --sarif fail (on 53 of 143 open-source apps we re-ran). Related locations now go through the same resolver as the main one. A new test passes every location shape through text, JSON, HTML, Markdown, SARIF and SonarQube output and checks that no path is missing or broken.
  • FixPaths with parentheses. Expo Router folders like app/(tabs)/index.tsx are kept whole, and a sentence's opening bracket no longer becomes part of a file name ((index.js).
  • TeamsPull request gate sees regressions, not only new ids. A finding whose severity went up, or the same problem appearing in a new file, now counts as new and can fail the gate. The PR comment lists them under "Worse" and "In new files".
  • AccuracyUnsure is not dead. When a project loads files by a computed path (require.context, import(variable)), no file is labelled as code nothing imports; folders given to require.context count as used. Security findings in unreached code keep their severity, and the label says "no import reaches", not "never runs".
  • AccuracyFewer files wrongly called unused. An import that names its extension (./CheckoutScreen.js) now reaches the file; files run by a package.json script, Node scripts run by hand, web service workers, Flow library definitions, files inside another project in the repository (its own package.json) and files read by name (readFileSync('sso.js')) count as used; code inside a string or in a build script no longer makes the whole check give up.
  • AccuracyA guard is not a leak. Code that reads EXPO_PUBLIC_SUPABASE_SERVICE_ROLE_KEY only to stop the app when it is set is no longer reported as shipping the key.
  • AccuracyLog silencing per method. A run-time no-op for console.log no longer hides console.info or console.debug calls, and a no-op inside a development-only branch does not count for release builds.

From a second production review: "the biggest gain is not more findings, but tying them to the right place, showing how strong the evidence is, and turning them into priorities".

  • AccuracyOld is not abandoned. A package with no release for two years is no longer described as "no fixes will come": the report says to check its repository, and native packages that are only old drop from high to medium. 20 October 2026

  • SecuritySupabase migrations: 28 of 45 databases analysed, up from 8. The policy checks stopped at any statement that might change a policy out of sight, and most real migrations have some: pg_dump's SET search_path, select cron.schedule(…), alter table … add column, and DO $$ … IF NOT EXISTS … CREATE POLICY … $$ blocks. 0.1.106

19 October 2026

  • SecurityKeys added at build time. An EXPO_PUBLIC_ value set in EAS, or a CI secret written into a .env on the build machine, is compiled into the app but never appears in the repository, so no source scan can see it. NativeKeel now opens the built app and scans the JavaScript bundle inside it: APKs and AABs under android/app/build/outputs, eas build --local results, committed bundles, and any APK, AAB or IPA passed with --artifact (or the GitHub Action's new artifact input, after your build step). 0.1.26

7 October 2026

  • StabilityPackages Expo did not test with your SDK. Each Expo SDK pins the library versions it is tested with. A native module from another release is one of the most common causes of build failures and launch crashes in Expo apps. NativeKeel now compares every pinned package (not only Reanimated, Screens and Gesture Handler) and rates the gap: a major difference is high, a minor one medium, a patch low. In our test set, 144 of 390 Expo apps with a lockfile have at least one, most often Reanimated, safe-area-context and Screens. The fix is one command: npx expo install --fix.

When a native library declares that it needs a newer React Native than the app has (Clipboard 1.14 needs 0.73, the app is on 0.72), builds commonly fail or the first call crashes. Only lower bounds count: loose upper caps such as ^0.60.0 on 0.62 are ignored, since apps run fine with them.
  • AccuracyA TLS bypass set on react-native-blob-util is judged by how requests use it: never used, it is not reported; tied to a setting (trusty: !certVerification, for self-hosted servers), it is high instead of critical. Found while checking well-known open-source apps.
  • PrivacyIn Expo projects without node_modules, NativeKeel asks unpkg for the versions your Expo SDK expects, sending only the expo version number. The privacy page, README and SECURITY.md list every request.
