React Native 0.87 · 0.88 · Expo SDK 58

Will your libraries build on React Native 0.88?

React Native 0.88 has no breaking changes of its own, but 0.87 had two that break libraries. Anyone coming from 0.86 or earlier, including every Expo SDK 57 app moving to SDK 58, meets both. We checked the 590 most downloaded React Native libraries with native code.

What breaks

iOS: React headers without React/. 0.87 ships its iOS headers as XCFrameworks, so a library that writes #import "RCTBridge.h" instead of #import <React/RCTBridge.h> stops the build with "file not found". We compiled every React Native 0.87.1 header both ways to know exactly which imports fail: details and a workaround. Then we built 15 of the 16 iOS libraries below, at the version listed, in a new React Native 0.87.1 app (Xcode 26.2): every one failed. The sixteenth, react-native-ios-context-menu, cannot be built on its own because it needs react-native-ios-utilities first.

JavaScript: APIs removed in 0.87. InteractionManager and the StatusBar methods setBackgroundColor, setTranslucent and setNetworkActivityIndicatorVisible are gone: development builds throw, release builds crash on the call (fix for InteractionManager). Calls behind a version check, in comments or in web-only files are not counted.

What this does not check

Android builds (0.87 also moves to Android Gradle Plugin 9), runtime behavior and anything outside these two changes. A library that passes here can still need an update for other reasons; a library listed here certainly does. The scan reads each library's published iOS and JavaScript sources from npm; nothing was executed except our own test builds.
